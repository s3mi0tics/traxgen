# traxgen — Decisions

Locked decisions about how this project works — architectural choices, conventions, and resolved tradeoffs. Once something is locked here, don't renegotiate it without raising a checkpoint. This file is the project's reasoning trail: it records not just *what* was decided but *why*, so a later session doesn't relitigate settled ground.

This is the decisions layer, distinct from its `allostatik/` siblings — `plan.md` holds current operational state (what's in flight), `observations.md` holds process patterns (how the work tends to go). Point at those rather than restating them here.

**Update protocol.** At session close, append decisions locked during the session. If a locked decision later changes, mark it rather than deleting it — the trail matters:

- `[SUPERSEDED <date>]` — full overturn. Replace the Choice with the marker plus a pointer to the row that replaces it.
- `[AMENDED <date>]` / `[PARTIALLY SUPERSEDED <date>]` — partial change where the original mostly holds. Prefix the marker to the Choice; leave the original text intact.

Always name the superseding or amending row so the trail stays followable.

| The live direction set is a measured table, not a derived rule (2026-08-08) | [AMENDED 2026-08-10 — the table is now complete: all six starter rotations swept exhaustively, and the pattern is parity (even → {E rot 1, NW rot 3}, odd → {NE rot 2}). | The sweep's positive control stays at starter rotation 0 (2026-08-08) | `sweep_goal_rotation.py --starter-rot N` sweeps every cell at N but pins the control at s=0, gives it kind `control_positive`, and excludes it from `classify()`'s per-direction tally | The app-certified geometry renders **inactive** at s=1, so a control that followed the swept rotation would abort every run but one, reporting `HARNESS_SUSPECT` for a healthy harness. Counting it as an observation of its own direction would invent an active NW cell at rotations where none exists |
| A model fitted to the record is tested by prediction, not by fit (2026-08-08) | When a model is built from prior data, the next run declares each cell's expected verdict **in code** before rendering, and the classifier compares outcome to prediction rather than deriving a mechanism from outcomes. `build_cells()` refuses to start if a declared prediction disagrees with the model's own function | Earned twice in one session. The parity model reproduced all 42 historical cells and still missed one of four predictions — fitting the record carries no evidence. And the starter sweep's free-text verdict asserted a mechanism the same run refuted: a pre-declared *trigger* and its *explanation* are separate claims, and only the trigger was tested |
| Connection knowledge is three-valued (2026-08-10) | `graph.py` classifies every starter/goal pair as `CONNECTED`, `DISCONNECTED`, or `UNMEASURED`, and `DISCONNECTED` is claimed **only inside the measured space** — at a swept starter rotation, where all 36 direction × rotation cells were rendered and a miss is a measured miss. Cross-layer pairs, out-of-range rotations, and anything else the record has not covered are `UNMEASURED`, never "no" | A two-valued API forces every unknown into a false claim, and the false claim it would pick ("not connected") is indistinguishable from a measured negative. The third value is what keeps the empirical discipline legible in code rather than only in prose |
| `START_GOAL_CONNECTED` severities mirror the epistemics (2026-08-10) | ERROR only when every starter/goal pair is *measured* disconnected; WARNING when the best evidence is `UNMEASURED`; silent when the course carries explicit rails (railed connection paths are unmodeled — open unknowns #2, #7) or has no starter/goal at all (that is `MISSING_STARTER_OR_GOAL`'s finding) | A validator that errors on unmeasured configurations converts a gap in the record into a false claim about the course, which is the same failure the frame guard exists to prevent one layer down (observations #17). One rule, one domain: absence and connection stay separate findings |
| The sweep queue stops on anything that questions the harness (2026-08-10) | `run_sweep_queue.py` **continues** past a mechanical hole — `INCOMPLETE` with no abort earns exactly one auto-resume, then the gap is recorded and the next rotation runs anyway — and past `MODEL_WRONG`. It **stops** the whole campaign on any abort (`harness`/`model`/`budget`), on `HARNESS_SUSPECT`, on a sweep that dies without writing results, and on any unmodeled exception | The gate moved from per-command to per-plan, not away. A hole in s=3 says nothing about s=4, and `MODEL_WRONG` questions the model while leaving later rotations honest measurements — both are safe to continue. Every stop condition instead implicates the *shared* harness or conditions, so continuing would spend renders on measurements no human has decided to trust |
| Containerizing the render loop is rejected for this Mac (2026-08-10) | Sweeps keep running from Colby's shell. The Android emulator needs hardware virtualization that Docker's Linux VM on an M1 does not expose; containerizing only the build/upload half would sandbox the safest part while `adb` — the part that touches something real — stays outside. Containment today comes from what already exists: the cloud sandbox for agent shell work, the Filesystem MCP allowlist as the standing grant, the emulator as its own sandbox, and git as the undo. **Trigger for revisiting:** a Linux host with KVM, at which point one throwaway container per run is the right architecture | Raised by Colby as a security measure ("make sure I don't accidentally give the wrong permissions"), which is a containment question distinct from the MAPE-K approval gate — both are wanted. But on this hardware the container buys isolation at the cost of the render engine, and the reviewed-script-plus-least-privilege story is stronger than the isolation it would trade away |
