# s46-t2 — the ring test board

**Status:** OPEN

**In one paragraph:** _written at close_

## Open (written before the work)

- **Goal:** a generator that lays out one ring per rotation of a piece across the standard four plates -- the launch pad on one side of the piece, a goal facing it on each other side, no two rings touching -- and a script that uploads it and prints the share code and which goal belongs to which rotation and side.
- **Scope:** `traxgen/ring_board.py`, `tests/test_ring_board.py`, `scripts/ring_board.py`.
- **Budget:** 60 minutes, one upload, no renders.
- **Done check:**
  1. *Step:* build `ring_board(TileKind.CURVE)` and upload it.
  2. *True after:* a course exists with six curve rings; every tile is on a buildable cell of the plate that owns it; no cell of one ring is next to a cell of another; `check_course` with the s46-t1 rule reads it INVALID only because rotations 0 and 4 load no marble, and each loading ring, checked on its own, is VALID; a share code exists for it.
  3. *Miss cases:* two rings touch, so a marble or a launch-pad connection crosses between tests; a tile sits on an uncompleted half-hole or off its plate and the app refuses it; the manifest names the wrong goal for a ring; only five rotations fit, and the generator silently drops one.
  4. *Reads:* the course built from the module, `plates`' footprints and half-holes, `layout.owning_plate`.
  5. *Check:* `uv run pytest tests/test_ring_board.py` passes, with tests that assert each of the four miss cases is absent on the curve board, and the script prints a code.
- **Outcomes declared before any live run:** none, because there is no live run in this task.
