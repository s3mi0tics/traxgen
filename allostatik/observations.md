# traxgen — Observations

Patterns noticed about how you and Claude work together on this project — frictions, recurring habits, things worth not losing. Numbered cumulatively across sessions; the numbers are stable references, so don't renumber when an observation moves.

This file has two sections. **Candidates** are patterns still being validated. **Promoted** are the ones durable enough to count as baseline expectations — a candidate promotes after it fires roughly three times across separate sessions (adjust the threshold in `workflow.md` if that doesn't fit your tempo).

A separate path runs to `decisions.md`: when an observation hardens into a commitment that constrains future work, it becomes a locked decision there, with the originating number noted for lineage. The two paths are independent — an observation can promote within this file, get locked as a decision, both, or neither.

**Update protocol.** The capture cadence lives in `workflow.md`; this file just holds the results. At session close: add new candidates, note any that fired again, promote the ones past the threshold, and retire candidates that have gone several sessions without firing.

## Promoted

1. **Integration canaries catch what synthetic unit tests miss.** Validating a real parsed fixture (GDZJZA3J3T, unlimited inventory) on every validator-rule commit has caught two real rule bugs that per-rule unit tests passed. Baseline expectation: any new rule ships with the canary green.
2. **Probe first, implement second.** When schema semantics are unknown, a small probe script against real fixtures beats reasoning from the spec — the retainer-family probe (fb2e547), the world-coord probe (3865bcb), the tile-index investigation, and the v7 byte-trace each settled a question that prose analysis had stalled on. Fired 4+ times. Stopping rule (refined 2026-07-22 from agentic-workflow-notes): probe until the next probe wouldn't change what you write — M6.a needed one probe, M4's retainer work needed many; the difference is whether each probe updates what gets built.
3. **App-built oracle fixtures are the ground truth of last resort.** Building a course in the real app and fetching its bytes via murmelbahn's `/api/course/{code}/raw` resolves format questions definitively — used for GDZJZA3J3T, 4YCV8JHLX7, and X3WEQ6F296; the last of these broke the rail-model question wide open.
7. **Tooling-first is the working style — flag automation before the third repetition.** If a manual flow involves more than ~3 repeated clicks/pastes/drags that will recur, stop and build the tool, even at a 20–30 minute detour — and Claude proposes this proactively rather than continuing the manual walk-through. Declared explicitly and demonstrated across M6.c (screenshot shell function, tap harness). Folded 2026-07-22 from `docs/refs/agentic-workflow-notes.md`.
8. **Multi-edit patch scripts with exact-match validation are the default for doc edits.** "Old must match exactly once" catches both drifted text (0 matches) and over-generic text (N matches); sed silently does neither. Validate against the *evolving* text, not a pre-pass on the original — a separate pre-validation phase breaks chained edits (discovered 2026-07-22 when this very fold-in aborted on its first run). Fired in M6.a, twice in M6.c, and throughout the migration.
12. **A check can pass while asserting something false — verify the claim, not the check.** Three firings, all in the 2026-07-27 repair session and its backfill: `decisions.md` locked Python 3.12 as "pinned `.python-version`" while that file had never existed (`a757183` gitignored it), so the lock and the reality had never once been compared; `plan.md` listed M5.b-fix as next when it had been done since `f6e5717`; and the session-log freshness check passed on 2026-07-27 while that very session went unlogged, because it reads the file that only gets written at close. The shared shape: the check compares two things with a common origin, so agreement is guaranteed and carries no information. Baseline expectation: when a check's pass would be indistinguishable from its never having run, verify the underlying claim directly — read the file, run the command — rather than trusting the green. **Fired four more times on 2026-08-07**, all in Claude-authored work: a test helper whose `elif` let an "inactive control" case silently set up an *active* control, so the test would have passed while checking nothing; an assertion that was wrong while the code under test was right (`(5,1)` written for `(5,5)`); the goal-rotation sweep's byte-identity precondition, which compared a variant against `generate_minimal()` — two things sharing an origin — and so could never have caught the thing it was guarding against, namely whether the generator still matched the app-certified artifact; and the handoff's "repo has a `.envrc`" claim, contradicted by a `direnv: unloading` line printed on every single command and read past three times, including once out loud as "harmless". **Fired twice more on 2026-08-08**: the starter-rotation sweep's printed verdict asserted a mechanism (`connectable directions are {s, s+2} mod 6`) that its own data refuted two rows above — the pre-declared *trigger* was sound and tested, the free-text *explanation* bolted onto it was neither; and two counts were stated in prose without being counted ("51 measurements" in conversation, "45 rendered cells" written into a test docstring), both wrong, both settled by one command. Counter-example the same day: `expect_disclaimer=True` was *assumed* to wait for the disclaimer because a comment said the disclaimer appears on first load — reading the four lines of code showed it fires an unconditional tap, and the app had been open 1d15h, so the first render would have tapped a coordinate with something else under it. Reading beat assuming, and it cost one grep. **Fired again 2026-08-10**, in conversation rather than in code: asked about `caffeinate`, Claude asserted that letting the display sleep was harmless because "the AVD renders regardless" — stated as fact, never checked, and wrong. A locked screen occluded the emulator window, macOS throttled its GPU, and a fixed-sleep render fired into a still-loading course. The correction was one flag (`-d`), the claim cost a hole in the s=4 sweep, and the tell was familiar: a confident mechanism sentence with nothing behind it. Total firings: ten.

## Candidates

4. **Pre-declared time budgets keep exploratory work honest.** The 2026-04-24 session's 4-hour app-integration budget forced a clean "stop when we've won" at ~2 hours and would have given a principled abort if cert-pinning had blocked. 6. **Chat-session file transfers flatten folders — stage collision-proof copies first.** Fired twice in the 2026-07-22 migration: two `README.md`s collided (one silently replaced the other) and a hidden dotfile didn't survive a Finder drag. When moving project files into a paste-based session, stage renamed, visible copies rather than dragging in place. 9. **Pre-declare stop conditions when the failure mode is predictable.** "If X happens, we stop — pushing through requires explicit argument." Applied proactively 2026-04-24 (the TLS-error rule for the iOS retry); sibling of #4's time budgets. One deliberate firing.
10. **Commit by "why," not by session.** Categorize the working tree by reason-for-existence and make one commit per reason (M6.a's four-cluster untangling); includes narrowing lint runs to touched files when the repo carries pre-existing debt. If explaining a commit takes two paragraphs, it's two commits.
11. **One command at a time in interactive sessions.** Issue exactly one command and wait for real output rather than stacking predicted next steps — keeps the agent's reasoning grounded in what actually happened. From agentic-workflow-notes; validated informally throughout the 2026-07-22 migration.
13. **Session attribution doesn't survive across execution surfaces.** Claude Code writes a `Claude-Session:` trailer into commit bodies; the web UI writes nothing. Reconstructing the 2026-08-03/04 rename session took one `git log` — the shared trailer on `7158605`, `f8ab4bf`, and `4988c41` proved three commits across two dates were one session, which collapsed the missed-close count from three to two and changed the correct response from double-loop to single-loop. The 2026-07-27 row had no such trace and was only recoverable because a chat session still held it. Consequence: when the close routine doesn't fire, git-legible sessions stay reconstructible and web-UI sessions decay to whatever conversation survives. One firing, but it determined the outcome of the session that found it.
14. **MCP filesystem reads hang while config-only calls return.** Three consecutive four-minute timeouts on `read_text_file` against `allostatik/plan.md` — a valid path inside an allowed root, which a shell script read and wrote successfully minutes later — while `list_allowed_directories` returned normally each time. Sharpens the existing note that `list_allowed_directories` is the more reliable call: the split appears to be disk-touching versus config-only, not tool-by-tool. The dead-roots hypothesis (two allowed roots pointing at retired `~/Desktop/Hub` paths, stalling disk calls while leaving config listing unaffected) is weakened: reads recovered later the same session with no config change and no restart, which points at transient server state rather than a path problem. Pruning the stale roots remains correct hygiene but is not the fix. Fired throughout 2026-08-04, intermittently, including a write timeout after reads had recovered. Leading explanation (Colby, 2026-08-04): the conversation was started on the web and never fully connected to the desktop-local MCP server, which would explain partial reachability that no config change resolves. Untested; the cheap test is whether a desktop-started conversation reads cleanly. **Cheap test run 2026-08-07**: a desktop-started session read seven canonical files (~60KB) in one call with no hang, and read/wrote throughout a long session without a single timeout. One data point, consistent with Colby's explanation. Not yet conclusive — but no longer untested.
15. **The upload endpoint fails transiently under batch load.** **Fired a third time 2026-08-10** — one cell of the s=2 sweep, mid-queue, during an unattended run; the queue's auto-resume closed it without a human present, which is the first time the recovery path ran with nobody watching. Three firings in three batch runs makes this the endpoint's normal behaviour under load, and it is now a *designed-for* condition rather than a surprise: `run_sweep_queue.py` treats `INCOMPLETE`-with-no-abort as mechanical and repairs it automatically. **Fired again 2026-08-08**: one cell of 43 returned HTTP 520 mid-batch, in a different position from the first, and the resume path closed the hole in a single render 40 seconds later — the design held exactly as intended. Two firings in two batch runs suggests this is the endpoint's normal behaviour under load rather than bad luck, and that any sweep longer than ~40 cells should expect at least one. Original entry: one cell of 42 returned HTTP 520 (Cloudflare edge, not a payload rejection) mid-batch on 2026-08-07. Recoverable only because uploads run as a batch *before* renders and `upload_error` is recorded as a field distinct from a missing verdict — so the run reported `INCOMPLETE` rather than classifying on a hole. Argues for keeping the upload-all-then-render-all ordering rather than interleaving. Two firings.
16. **Exonerate the obvious suspect before diagnosing.** When `ime_ok` stopped working the intuitive cause was a stale tap coordinate; one `uiautomator dump` ruled it out (`[2216,252][2384,378]` contains (2270,305)) and redirected the entire diagnosis to timing. Cheap elimination of the likely-but-wrong cause beat reasoning forward from symptoms, and would have saved hours spent re-measuring coordinates. One firing.
17. **Guard the failure that invents data, not just the one that loses it.** **Fired again 2026-08-10, and this time the guard was the only thing watching.** A locked screen throttled the occluded emulator; a fixed-sleep render sampled a loading screen at `white_frac` 0.653. Without the frame guard the oracle would have returned a brightness-driven verdict into an unattended run and no human would have seen the frame — the screenshot is pruned unless it is a failure or an active. Instead it raised, the cell was recorded as a hole, and one auto-resume closed it. The 2026-08-07 lesson (weight guards by what a wrong answer would be *believed* to mean) compounds under automation: unattended runs remove the human who would have noticed. Two firings. The 2026-08-07 harness failed twice in opposite directions. The IME desync made the oracle return `inactive` for a keyboard — a null result, which reads as "no finding" and costs a re-run. The splash screen made it return `active` — a *positive* result, which reads as a discovery and would have been recorded as `MODEL_WRONG`. Same oracle, same magnitude of bug, wildly different blast radius. When ranking guards, weight by what a wrong answer would be *believed* to mean. One firing, but it determined which fix shipped first.
18. **A pre-declared threshold is only as good as the model behind it.** The sweep's image-diff check was pre-declared as "a few percent of the frame" for a real difference; the real answer was 0.07%, because the camera sits far enough out that a two-tile course occupies a sliver of the frame — a fact not known when the number was chosen. Declaring it early was still right: it forced an escalation to direct inspection instead of allowing a post-hoc rationalisation in either direction. The lesson is not "don't pre-declare" but "pre-declare the *decision procedure*, and treat a missed threshold as a trigger to look harder rather than a verdict." One firing.
19. **Free-text narration attached to a passing check is untested output.** The starter-rotation sweep's `classify()` fired the right branch on the right trigger and then printed a mechanism its own run refuted. Every pre-declared condition had a test; the sentence explaining what the condition *meant* had none, and it was the sentence that would have been copied into `decisions.md`. Sibling of #12 and #18, distinct in its fix: the follow-up sweep declares each cell's expected verdict **in code**, and `build_cells()` raises if the declared table and the model function disagree — so there is no free-text mechanism claim left for a run to get wrong. One firing, but it nearly wrote a false finding into canonical state.
20. **Reproducing the record is not evidence; only prediction is.** **Fired again 2026-08-10, on the winning side.** With s=2 and s=3 measured, parity (even → {E, NW}, odd → {NE}) was stated in conversation as an explicit forward prediction for s=4 and s=5 *before* their renders ran — and both landed. Same discipline as the 2026-08-08 firing, opposite outcome, which is what makes the pair informative: the rule earns belief by surviving a declared test, not by fitting the rows behind it. Also the reason `graph.py`'s table refuses to interpolate even now that all six rows exist — a pattern that survived prediction is still a pattern, not a mechanism. Two firings. The parity model was encoded as a test that replays all 42 previously-rendered cells, and it passed every one — then missed one of its four forward predictions on the very next run. A model built from a dataset explains that dataset by construction, so a green replay says nothing about correctness; it only guards against later edits silently breaking an old observation, which is a real but much smaller job. Worth keeping both, and worth not confusing them. One firing.
21. **Before running an experiment, ask what a null result would prove.** Fired twice on 2026-08-08. The handoff proposed sweeping the starter against a *mispredicted* cell (NE rot 2); six inactives there would have been equally consistent with "the direction is unreachable" and "the coupling is real but never yields rot 2 here" — a null that discriminates nothing. Swapping to a *known-active* cell made both outcomes informative at identical cost. Later the same session, choosing the full 36-cell sweep at s=1 over a 2-cell probe turned an expected null into a positive fact about the space: not "SW and SE didn't connect" but "exactly one cell in 36 connects". The cheap probe would have spent two renders and left the question open. The test is not "is this cheap" but "does every outcome move me".
22. **Automating a manual loop relocates the gate; it does not remove one.** Colby's ask on 2026-08-10 was "a lot of these sweeps are not decisions I am making — can we have a plan and let it go." The right read was not "remove approval" but "approve at the right altitude": the per-command gate had been protecting *nothing* for the mechanical steps (reset, settle, relaunch, resume a 520) while genuinely protecting the meaningful ones (is the oracle lying, is the model wrong). `run_sweep_queue.py` moved the gate from per-command to per-plan — one launch approves a declared campaign, and the harness-questioning conditions still halt and wait for a human. The diagnostic question when something feels like busywork: *which of these steps is a decision?* Everything else is a candidate for automation, and the answer names the new gate rather than deleting it. One firing.
23. **Unattended runs make the environment part of the harness.** Everything under test on 2026-08-10 was correct — the queue, the sweep, the oracle, the resume path — and the run still lost a cell, because the *machine* changed state: the screen locked, macOS throttled the occluded emulator's GPU, and a fixed sleep expired into a loading screen. Attended runs hide this class of failure, since a human is present precisely because they are watching the screen that would otherwise sleep. The moment a run is designed to proceed alone, the host's power management, display state, and window occlusion stop being background and become preconditions to declare (here: `caffeinate -d -w <pid>`, which also self-terminates with the run). Sibling of #21 — both are about asking what the run assumes before spending it. One firing, and it argues for `plan.md` item 2 (polling waits), which would absorb this class rather than trip on it.
