# s38-t2 — a failed run keeps the phone's account

**Status:** STOPPED — needs Colby: the live proof, (e), has to run on the Mac. Will you run the next `--fresh` render there, and if it fails, check that stderr shows `device evidence saved: <path>` before the last `emulator_down` line and that the file has a meminfo section and a logcat section? If it passes, a failure can be forced by running `adb shell am force-stop com.ravensburger.gravitrax` during the menu wait.

**In one paragraph:** a failed `--fresh` render now leaves the phone's own account behind. When the device checks fail or the render raises, `emulator.session()` saves the phone's memory report (`dumpsys meminfo`) and its whole log (`logcat -d -b all`) to one file under `screenshots/device_evidence/`, before the teardown kill wipes them, and prints the path. If the phone refuses a command, adb's words go into the file and the capture carries on, because a phone that cannot answer is part of #20's answer. A clean run and a Ctrl-C save nothing, and a capture that fails never blocks the teardown or hides the render's own error. Offline, 14 tests and 11 mutants hold this. The one step left is the live proof, a real failed render on the Mac leaving the file behind, and only Colby can run it.
